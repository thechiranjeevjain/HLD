# Production Incidents

Use this catalog as a runbook and interview drill set. For each incident, practice saying the symptom, proving the failing boundary, naming the root cause, fixing it, and adding prevention.

| #   | Incident                        | Symptoms                                          | Logs                                                    | Root Cause                                                      | Investigate And Commands                                                                                       | Expected Observations                                        | Fix                                                        | Prevention                                         | Interview Question                                            |
| --- | ------------------------------- | ------------------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------- |
| 1   | CrashLoopBackOff                | Pod restarts repeatedly; service unavailable.     | `Started...` followed by stack trace and exit.          | App process exits during startup.                               | `kubectl -n mini-risk describe pod <pod>`; `kubectl -n mini-risk logs <pod> --previous`.                       | Restart count increases; previous logs show fatal exception. | Fix config, dependency, or code crash; redeploy.           | Startup smoke tests and safer config validation.   | What does CrashLoopBackOff mean?                              |
| 2   | OOMKilled                       | Pod restarts under load; latency spikes.          | Previous logs may stop abruptly.                        | Container exceeded memory cgroup limit.                         | `kubectl describe pod <pod>`; `kubectl top pod <pod>`.                                                         | Last state shows `OOMKilled`; exit code 137.                 | Increase limit, reduce heap, fix leak.                     | Heap sizing, memory alerts, load tests.            | Why is Java heap not total container memory?                  |
| 3   | ImagePullBackOff                | Pod never starts.                                 | Kubelet events show pull failure.                       | Wrong image tag, registry, or credentials.                      | `kubectl describe pod <pod>`; inspect Events.                                                                  | `ErrImagePull` then `ImagePullBackOff`.                      | Push image or correct image name.                          | CI image build and deployment validation.          | How does Kubernetes pull images?                              |
| 4   | Wrong ConfigMap                 | Service starts with wrong downstream URL.         | Connection errors to wrong hostname.                    | Bad ConfigMap value injected into env.                          | `kubectl get configmap mini-risk-config -o yaml`; `kubectl exec <pod> -- printenv`.                            | Env var contains wrong value.                                | Patch ConfigMap and restart Pods.                          | Config review, schema validation, canaries.        | Do ConfigMap env vars update live?                            |
| 5   | Wrong Secret                    | DB-backed service is unready.                     | `password authentication failed`.                       | Secret contains wrong password or key.                          | `kubectl get secret mini-risk-secrets -o yaml`; `kubectl logs deployment/order-service`.                       | Hikari cannot create connections.                            | Restore Secret and restart affected Pods.                  | External secrets, rotation tests, least privilege. | Are Kubernetes Secrets encrypted by default?                  |
| 6   | Volume Deleted                  | Data disappears after restart.                    | DB initializes as empty.                                | Docker volume or PV data removed.                               | `docker volume ls`; `kubectl get pv,pvc`; query row counts.                                                    | Tables exist but previous rows are gone.                     | Restore from backup or recreate seed data.                 | Backups, retention policy, careful `down -v`.      | What is the difference between container layer and volume?    |
| 7   | Network Timeout                 | Gateway returns 503 after waiting.                | `ResourceAccessException` or connect timeout.           | Service name, port, or network path broken.                     | `kubectl exec deployment/api-gateway -- wget -S -O- http://order-service:8081/actuator/health`.                | DNS may work but TCP or HTTP fails.                          | Correct Service, port, or NetworkPolicy.                   | Synthetic checks and dependency timeouts.          | How do you distinguish DNS failure from TCP timeout?          |
| 8   | Database Unavailable            | Orders fail; DB-dependent Pods unready.           | `Connection refused` or `timeout acquiring connection`. | PostgreSQL down or unreachable.                                 | `kubectl get pods -l app=postgres`; `kubectl logs deployment/postgres`; `psql` check.                          | Postgres Pod missing, unready, or rejecting connections.     | Restart or restore Postgres.                               | Managed DB, backups, readiness alerts.             | What should happen to risk checks when DB is down?            |
| 9   | Kafka Unavailable               | Orders stored but exposure and notifications lag. | Producer send failures or consumer disconnects.         | Kafka broker down or listener misconfigured.                    | `docker compose exec kafka kafka-topics.sh --bootstrap-server localhost:9092 --list`; consumer group describe. | Broker command fails or lag increases.                       | Fix broker and retry publishing; use outbox in production. | Kafka health alerts and outbox pattern.            | Why can DB commit plus Kafka publish lose events?             |
| 10  | Redis Unavailable               | Risk checks slower but still work.                | `risk-limit cache read skipped`.                        | Redis down or network failure.                                  | `docker compose logs redis`; `redis-cli ping`; risk logs.                                                      | Cache warnings, DB fallback.                                 | Restart Redis.                                             | Cache fallback, hit-rate alerts, TTLs.             | Should cache failure fail the request?                        |
| 11  | Pod Deleted                     | Brief capacity reduction.                         | Normal termination logs.                                | Human or controller deleted Pod.                                | `kubectl get pods -w`; `kubectl get events`.                                                                   | Replacement Pod created by ReplicaSet.                       | Usually no fix; wait for readiness.                        | Pod disruption budgets and replica count.          | Why does deleting a Pod not delete the app?                   |
| 12  | Node Failure                    | Many Pods disappear or reschedule.                | Node NotReady events.                                   | Worker node failed or unreachable.                              | `kubectl get nodes`; `kubectl describe node <node>`.                                                           | Pods stuck Terminating or rescheduled.                       | Restore node or let scheduler move Pods.                   | Multi-node replicas and PDBs.                      | What happens to Pods on a failed node?                        |
| 13  | Container Restart               | Service recovers but loses in-memory state.       | Startup log appears again.                              | Process crash, probe failure, or OOM.                           | `kubectl describe pod <pod>`; check restart count.                                                             | `restartCount` increments.                                   | Fix underlying reason.                                     | Alerts on restart rate.                            | What is the difference between restart and reschedule?        |
| 14  | Disk Full                       | DB writes fail; Kafka may stop.                   | `No space left on device`.                              | Volume or node filesystem full.                                 | `df -h`; `kubectl describe node`; DB logs.                                                                     | Disk pressure events or write failures.                      | Expand storage or delete safe old data.                    | Disk alerts, retention, WAL monitoring.            | Why can disk full take down unrelated Pods?                   |
| 15  | Memory Leak                     | Latency worsens then OOMKilled.                   | Heap grows; GC frequent.                                | Objects retained unexpectedly.                                  | Prometheus `jvm_memory_used_bytes`; heap dump if enabled.                                                      | Heap trend rises until limit.                                | Fix retention bug or tune heap.                            | Leak tests and heap alerts.                        | How do you prove a memory leak?                               |
| 16  | Ingress Misconfiguration        | `mini-risk.local` returns 404 or 502.             | Ingress controller logs backend error.                  | Wrong host, path, class, or Service backend.                    | `kubectl describe ingress mini-risk-ingress`; controller logs.                                                 | Rule does not match or backend endpoints missing.            | Correct Ingress host/path/service.                         | Ingress smoke tests.                               | What is Ingress versus Service?                               |
| 17  | Service Selector Mismatch       | Service has no endpoints.                         | Gateway times out; app Pods look healthy.               | Service selector does not match Pod labels.                     | `kubectl get svc,endpointslice`; compare labels.                                                               | EndpointSlice empty.                                         | Fix selector or Pod labels.                                | Label conventions and validation.                  | Why can healthy Pods receive no traffic?                      |
| 18  | Port Mismatch                   | Connection refused through Service.               | `Connection refused` to expected port.                  | Service `targetPort` differs from container port.               | `kubectl describe svc order-service`; `kubectl describe pod <pod>`.                                            | Service routes to wrong port.                                | Fix `targetPort` or container port.                        | Port naming and integration checks.                | Difference between `port`, `targetPort`, and `containerPort`? |
| 19  | DNS Failure                     | Service name cannot resolve.                      | `UnknownHostException`.                                 | CoreDNS issue or wrong name/namespace.                          | `kubectl exec <pod> -- nslookup risk-service`; `kubectl -n kube-system logs deployment/coredns`.               | DNS query fails.                                             | Fix name or restore CoreDNS.                               | DNS probes and namespace-aware URLs.               | How does Kubernetes DNS search path work?                     |
| 20  | Readiness Probe Failure         | Pod running but no traffic.                       | Actuator readiness reports down.                        | Dependency not ready or app health indicator down.              | `kubectl describe pod <pod>`; call readiness URL.                                                              | Pod Ready=false; Service endpoints omit Pod.                 | Fix dependency or readiness config.                        | Separate liveness from readiness.                  | Why not use liveness and readiness the same way?              |
| 21  | Liveness Probe Failure          | Pod restarts even though it might recover.        | Probe failed events.                                    | Probe too aggressive or endpoint slow.                          | `kubectl describe pod <pod>`; check latency.                                                                   | Restart count follows probe failures.                        | Relax probe or fix endpoint.                               | Avoid dependency-heavy liveness probes.            | What makes a bad liveness probe dangerous?                    |
| 22  | Resource Starvation             | High latency; few restarts.                       | CPU throttling visible in metrics.                      | CPU limits too low or noisy neighbor.                           | `kubectl top pods`; Prometheus CPU metrics.                                                                    | CPU near limit; latency rises.                               | Raise CPU limit or optimize hot path.                      | Load tests and CPU alerts.                         | What is CPU throttling?                                       |
| 23  | High CPU                        | Risk service saturates.                           | No errors, slow responses.                              | Expensive calculation, logging loop, or GC pressure.            | `kubectl top pods`; Java thread dump.                                                                          | One or more threads consume CPU.                             | Fix loop or scale out.                                     | Profiling and performance tests.                   | How do you debug high CPU in Java?                            |
| 24  | Slow Queries                    | Risk or history latency increases.                | SQL timings high.                                       | Missing index or table scan.                                    | `EXPLAIN ANALYZE`; DB slow query logs.                                                                         | Sequential scan or lock wait.                                | Add index or rewrite query.                                | Query plan review and indexes.                     | Why can an index hurt writes?                                 |
| 25  | Connection Pool Exhaustion      | Requests wait then fail.                          | `Connection is not available`.                          | Too many concurrent DB requests or leaked connections.          | Hikari metrics; DB `pg_stat_activity`.                                                                         | Active connections at max.                                   | Tune pool, fix slow query/leak.                            | Pool alerts and timeouts.                          | How do you size a connection pool?                            |
| 26  | Thread Pool Exhaustion          | HTTP requests queue.                              | Timeout errors without DB saturation.                   | Server worker threads blocked.                                  | Thread dump; Tomcat metrics.                                                                                   | Many threads blocked on I/O.                                 | Add timeouts or tune pool.                                 | Bounded pools and bulkheads.                       | What is thread pool starvation?                               |
| 27  | GC Pause                        | Latency spikes with no CPU max.                   | Long GC pause logs.                                     | Heap pressure or bad allocation rate.                           | JVM GC metrics; enable GC logs.                                                                                | Pause time correlates with latency.                          | Reduce allocations or tune heap/GC.                        | GC dashboards and load tests.                      | How does GC affect tail latency?                              |
| 28  | Deadlock                        | Requests hang forever.                            | Thread dump shows deadlock.                             | Locks acquired in inconsistent order.                           | `jcmd Thread.print`; actuator threaddump if enabled.                                                           | Deadlocked thread report.                                    | Fix locking order or remove locks.                         | Concurrency tests and lock discipline.             | How do you prevent deadlocks?                                 |
| 29  | Kafka Consumer Lag              | Exposure updates delayed.                         | Consumers alive but behind.                             | History consumer slower than producer.                          | `kafka-consumer-groups.sh --describe`; app logs.                                                               | Lag grows on partitions.                                     | Scale consumers, optimize DB writes.                       | Lag alerts and partition strategy.                 | Why can lag grow even when consumers are healthy?             |
| 30  | Poison Message                  | Consumer repeatedly fails same record.            | Deserialization or processing exception.                | Bad event schema or unexpected payload.                         | Consumer logs; inspect topic record.                                                                           | Same offset retried.                                         | Send to DLQ or fix deserializer.                           | Schema registry and DLQ.                           | How do you handle poison messages?                            |
